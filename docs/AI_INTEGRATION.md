# ربط نموذج الذكاء الاصطناعي — عَزْم | AZM

## فصل الاستخراج والمحادثة والتقارير

واجهة «مساعد عزم الذكي» محادثة مباشرة فقط: مربع كتابة وإرسال ومحادثة جديدة وسجل محفوظ بأسماء المحادثات وتواريخها. Enter يرسل وShift+Enter يضيف سطراً. لا توجد قائمة نوع الرسالة أو اختيار وحدة أو استخراج مسودة أو اقتراحات جاهزة. تبدأ المحادثة عبر `POST /api/chats` وتستمر عبر `POST /api/chats/:id/messages`؛ حالة الاتصال من `/api/ai/status` تخص نموذج المحادثة الأساسي وحده.

التشغيل المحلي بالنموذج الأساسي على 8002 يستخدم `AZM_AI_PROVIDER=openai` و`AZM_AI_BASE_URL=http://127.0.0.1:8002/v1` و`AZM_AI_MODEL=azm-report-base`، كما في `start-azm.cmd` / `start-azm.sh`. يبقى الوضع الافتراضي `none` صالحاً. أدابتر الطلب على نفس الخدمة 8002 باسم `azm-request-lora` عبر `AZM_REQUEST_AI_*` وAPI المسودة. التقرير الذكي في سجل العمليات يستخدم `AZM_REPORT_AI_*`، وهو محلياً نفس النموذج على 8002، ويستخدم RAG عبر `AZM_RAG_URL` (BGE-M3 على 8010). خطوات التشغيل الكاملة والمتطلبات في [SETUP.md](SETUP.md).

نطاق لقطة السياق وأدوات `read_inventory` و`read_requests` و`read_report` مشتق من حساب الجلسة على الخادم: مسؤول الوحدة يرى وحدته ومخزونها وطلباتها وتقاريرها وأسماء سلسلة إمدادها فقط؛ مسؤول القاعدة يرى قاعدته ومراكزها ووحداتها فقط؛ القائد يرى الجميع. تعيد أداة القراءة اشتقاق النطاق أيضاً عند استدعائها داخلياً. المعرّف المحظور يعيد `out_of_scope` (وHTTP 403 عند الاستدعاء المباشر). لا يمنح نص المستخدم أو معرّف يرسله المتصفح صلاحية إضافية، ولا يتحول رد النموذج إلى طلب أو حركة أو اعتماد.

أداة القراءة الرابعة `read_locations` (`{ nodeId? }`) ترجع اسم كل جهة ونوعها ورمزها وخط العرض والطول، بنفس نطاق الخريطة: القائد الكل، ومسؤول القاعدة قاعدته وتوابعها والقاعدة الرئيسية، ومسؤول الوحدة وحدته وسلسلة إمدادها. الجهة خارج النطاق ترجع `out_of_scope`.

أداة القراءة الخامسة `read_users` (`{ username? }`) ترجع لكل حساب: اسم المستخدم، والاسم، والرتبة، والدور، والحالة، والوحدة وموقعها على الخريطة (`unitNodeId`)، والقاعدة. لا ترجع كلمة المرور ولا الرقم العسكري ولا الجوال. نطاقها نفس صفحة الحسابات: القائد الكل، ومسؤول القاعدة حسابات قاعدته، ومسؤول الوحدة حسابه فقط. الحساب خارج النطاق يرجع `out_of_scope`. وأسئلة الهوية («من أنا؟»، «وش صلاحياتي؟»، وادعاء الدور لحاله مثل «أنا القائد») يجاوبها الخادم مباشرة من حساب الجلسة بدون النموذج (`server/ai/identity.mjs`).

### الأجوبة المباشرة من الخادم
الحقائق الدقيقة (مين الشخص، ووين موقعه، وكم إحداثياته) يجاوبها الخادم بنفسه، والنموذج للتحليل والشرح:

| نوع السؤال | من يجاوب | الملف |
|---|---|---|
| من أنا؟ / وش صلاحياتي؟ / أنا القائد / أنا العقيد فلان القايد الرئيسي | الخادم | `identity.mjs` |
| من فلان؟ / من النقيب علي؟ / من القائد الرئيسي؟ | الخادم، من الحسابات الظاهرة | `identity.mjs` |
| إحداثيات / وين: كل الوحدات، كل القواعد، مراكز الإمداد، القاعدة الرئيسية، جهة بالاسم، شخص | الخادم، من الخريطة | `direct.mjs` |
| كل شي غيرها (المخزون، والطلبات، والتحليل، والتوصيات، والقواعد العامة) | النموذج | كما هو |

- الإحداثيات بنفس نطاق الخريطة (`scope.nodeIds`)، والأشخاص بنفس نطاق صفحة الحسابات، وأي شي خارج النطاق يرد بجملة الرفض الثابتة.
- الخادم يجاوب بس لما يتعرف على المقصود بشكل أكيد (اسم حساب موجود، أو جهة موجودة، أو مجموعة معروفة). غير كذا يروح السؤال للنموذج؛ مثلاً «من وين تتموّن القواعد؟» يروح للنموذج.

ترتيب رسائل المساعد للنموذج: البرومبت الثابت ← لقطة البيانات المفلترة ← مقاطع المنهجية ← رسالة «Signed-in account» ← سجل المحادثة. رسالة الحساب يبنيها الخادم من الجلسة (اسم المستخدم والاسم والرتبة والدور بجملة صريحة)، وما فيها كلمة مرور ولا جلسة، وادعاء الدور في كلام المستخدم ما يغيّرها. وصار `viewer` في اللقطة يحمل `fullName` و`rank`.

التحقق: `node scripts/assistant-chat-test.mjs` يختبر اللقطة والأدوات والأدوار الثلاثة وعدم تغيير المخزون والطلبات، وهو ضمن smoke-test. `node scripts/assistant-chat-ui-test.mjs` يفتح Chromium بثلاث جلسات تبويبات، ويختبر Enter والزر والأسئلة المسموحة والمحظورة والسجل والتحديث. يستخدم الاختباران نموذجاً تجريبياً حتمياً وبيانات ومنافذ مؤقتة؛ لا يثبتان جودة استدلال النموذج الحقيقي على 8002. بعد تعديل الخادم يلزم إعادة تشغيله ثم تحديث الصفحة؛ الاختبارات لا توقف خادم التشغيل الحالي.

- **استخراج الطلب (API للتوافق):** إعدادات مستقلة `AZM_REQUEST_AI_PROVIDER` و`AZM_REQUEST_AI_MODEL` و`AZM_REQUEST_AI_BASE_URL` و`AZM_REQUEST_AI_API_KEY` و`AZM_REQUEST_AI_TIMEOUT_MS`؛ عند غيابها تُقرأ إعدادات `AZM_AI_*` للتوافق القديم. LoRA مخصص لتحويل نص طلب الإمداد إلى JSON. يبقى `/api/ai/request-draft` ويطبق الخادم عقد `extract_supply_request`، دون زر في واجهة المحادثة المباشرة. يطابق أسماء الأصناف مع الكتالوج ويرفض غير المعروف أو الملتبس، ويأخذ الفئة من الكتالوج مع تحذير عند اختلاف النموذج. يتحقق من تعيين المادة والكمية والوحدة والتحويل؛ الناقص يبقى ناقصاً. لا ينشئ الاستخراج طلباً ولا حركة مخزون؛ إغفال `deadline` يطبّع إلى `null` مع تحذير دون اختراع موعد.
- **المحادثة العامة:** `AZM_AI_*` لنموذج إجابة منفصل على أسئلة الحالة والاستخدام ضمن بيانات الحساب المفلترة. أدوات القراءة في `GET /api/ai/tools` تُنفذ عبر تحقق الخادم فقط؛ لا توجد أدوات إنشاء أو اعتماد أو صرف للنموذج. `POST /api/ai/tools/read` يقبل `{name,arguments}` وفق المخطط المعلن، ويرفض الحقول الزائدة والنطاق الخارجي.
- **التقرير الذكي للعمليات:** داخل صفحة سجل العمليات، وأزيلت صفحة «شات التقارير». يكتب تقريراً لعملية واحدة أو عمليات محددة أو فترة وفلاتر، ويقبل أسئلة لاحقة. الخادم في `server/ai/ops-report.mjs`:
  - يحسب كل الإجماليات من العمليات المختارة بنطاق الحساب.
  - **يكتب قسم «أبرز الأرقام» بنفسه** بترتيب: المطلوب في الطلبات القائمة، ثم المرفوض، ثم الحركات التشغيلية، والتموين الافتتاحي في سطر واحد.
  - يعطي النموذج **حقائق نصية جاهزة بلغة الرد** بدل JSON، وفيها سطر لكل طلب بحالته وذكر صريح لما لم يحدث، ضمن `AZM_REPORT_AI_CONTEXT_CHARS` (افتراضي 10000)، ويعيد المحاولة بنصف الحد إذا كان السياق طويلاً.
  - النموذج يكتب الملخص والملاحظات والتوصيات فقط.
  - النص يُنظَّف قبل العرض: تُحذف رموز الأنواع والكلمات الدخيلة والتوصية المتناقضة.
  - بدون نموذج تظهر الأرقام كاملة مع تنبيه.
  - يسترجع فقرات منهجية عزم عبر BGE-M3 (`AZM_RAG_URL`، خدمة `scripts/start-rag.sh`)، أو بالبحث المحلي احتياطاً، ويحفظ مع الرد `sources` و`ragSource`. التفاصيل في [RAG_SETUP.md](RAG_SETUP.md).
- **شات التقارير (مسارات للتوافق، بلا صفحة في الواجهة):** مسارات `/api/report-chats` ومجموعة إعدادات مستقلة `AZM_REPORT_AI_*`، ويستخدمها أيضاً زر شرح التقرير في صفحة «التقارير». التقرير يُحسب على الخادم بنطاق الحساب، ويرسل للنموذج كأرقام حديثة. الدالة `retrieveReportContext(question, scope)` في `server/ai/report.mjs` تبحث في مرجع عزم المحلي `resources/report-knowledge.json`، ويمكن وصل مسترجع خارجي عبر `AZM_RAG_URL` وعقد النطاق في القسم الأخير. لا توصل مستندات خارج النطاق ولا تعتبر المستندات مصدراً لرصيد حي.
- الأصناف الأربعون مستخرجة من `rag_data.zip` في `resources/items.json`، مع المعرف الإنجليزي والوحدات والتحويلات. SOP والجهات الخيالية مستبعدة عمداً لأنها تختلف عن صلاحيات عزم.

مثال رد نموذج الاستخراج:

```json
{"items":[{"item":"rice","supply_class":"I","quantity":2,"unit_of_measure":"bag"}],"priority":"high","deadline":"tomorrow"}
```

بعد التحقق تصبح الكمية `50 kg` في المسودة؛ لا يتحرك أي مخزون بمجرد رد النموذج. لربط نموذج التقارير بشكل مستقل عيّن `AZM_REPORT_AI_PROVIDER=openai` مع `AZM_REPORT_AI_BASE_URL` و`AZM_REPORT_AI_MODEL` في `.env`.

المساعد الذكي (الزر الدائري أسفل يمين الشاشة) **جاهز للربط**.

طلبات الشات وشرح التقارير تمر عبر `api()` بجلسة التبويب (`X-Azm-Tab` + كوكي `HttpOnly` خاص). يحدد الخادم صاحب الطلب قبل بناء سياق النموذج؛ دخول حساب آخر في تبويب عادي لا يبدّل صاحب المحادثة أو نطاقها. لا يصل معرّف الجلسة أو رمزه للنموذج.

- **بدون نموذج:** يحفظ المحادثات ويرد "النموذج غير مربوط حالياً".
- **مع نموذج:** يجاوب على أسئلة الفريق باستخدام **بيانات النظام الحية**: المخزون، والطلبات، والتنبيهات، والمستودعات.

> **الخلاصة:** الربط من **الإعدادات فقط** (ملف `.env`)، بدون تعديل أي كود. أي خادم نماذج يدعم **OpenAI Chat Completions API** يشتغل مباشرة.

## 1) كيف يشتغل الربط

```
المستخدم يكتب سؤال في المساعد
   │
   ▼
POST /api/chats                     (server/routes/chats.mjs)
   │
   ▼
generateReply(user, chat)           (server/ai/index.mjs)  ◄── نقطة الربط الوحيدة
   │
   ├─ AZM_AI_PROVIDER=none   → يرد { kind: "not_connected" }      ← الوضع الافتراضي
   │
   └─ AZM_AI_PROVIDER=openai → يرسل للنموذج 3 أشياء:
         1. تعليمات النظام وشكل الرد        server/ai/prompt.mjs
         2. لقطة العمليات الحية (JSON)     server/ai/context.mjs  (مفلترة حسب صلاحية السائل)
            مصغّرة لتناسب سياق النموذج     server/ai/compact.mjs  (AZM_AI_CONTEXT_CHARS)
            + الموارد/المواقع المذكورة في السؤال بأرقامها الفعلية (askedResources)
         3. آخر رسائل المحادثة (حتى 20) ضمن ربع حد الأحرف
      ◄── إذا رد النموذج أن الطلب أطول من سياقه: إعادة بنصف الحد (مرتين)
      ◄── نص الرد ينحفظ في chats.json ويظهر للمستخدم
```

| الملف | دوره | متى تعدّله |
|---|---|---|
| `server/ai/index.mjs` | يختار الموصّل ويبني الرسائل ويعالج الأخطاء | لإضافة نوع موصّل جديد |
| `server/ai/prompt.mjs` | **تعليمات النظام** للنموذج | لتغيير أسلوب الردود وقواعدها |
| `server/ai/context.mjs` | البيانات اللي تنرسل للنموذج | لإضافة بيانات أو إخفائها |
| `server/ai/compact.mjs` | تصغير اللقطة ونتائج الأدوات لحد الأحرف، ومطابقة السؤال بالموارد والمواقع | لتغيير أولويات ما يُرسل عند ضيق السياق |
| `server/ai/report.mjs` | شرح التقارير، والاسترجاع (BGE-M3 أو محلي) وحالة RAG | لتغيير طريقة صياغة شرح التقرير |
| `server/ai/ops-report.mjs` | التقرير الذكي لسجل العمليات: الإحصاءات، الحقائق، «أبرز الأرقام»، التنظيف | لتغيير شكل التقرير أو محتواه |
| `server/ai/providers/openai-compatible.mjs` | الاتصال الفعلي بخادم النموذج | نادراً |
| `server/config.mjs` (قسم `AI`) | قراءة الإعدادات | نادراً |

## 2) الربط خطوة بخطوة — Ollama على نفس الجهاز (الأسهل)

### أ. ثبّت Ollama وحمّل نموذج

1. حمّل Ollama من https://ollama.com وثبّته. يشتغل تلقائياً على المنفذ `11434`.
2. في Terminal:
   ```bash
   ollama pull qwen2.5:7b
   ```
3. تأكد إنه شغّال:
   ```bash
   ollama run qwen2.5:7b "مرحبا"
   ```

### ب. أنشئ ملف `.env`

انسخ `.env.example` باسم `.env` في جذر المشروع، وعدّل هذي الأسطر:

```ini
AZM_AI_PROVIDER=openai
AZM_AI_BASE_URL=http://localhost:11434/v1
AZM_AI_MODEL=qwen2.5:7b
AZM_AI_TIMEOUT_MS=180000
```

استخدم اسم النموذج الموجود عندك في `ollama list` بدل المثال أعلاه. أول طلب قد يستغرق أكثر من دقيقة عند تحميل النموذج.

### ج. أعد تشغيل الخادم

```bash
node server.mjs
```

لازم يطبع:

```
AI assistant: connected (openai · qwen2.5:7b)
```

### د. جرّب

افتح المساعد. تحت الاسم لازم تطلع **نقطة خضراء** ومكتوب "متصل — qwen2.5:7b". اسأل مثلاً:

- "وش أكثر وحدة تحتاج إمداد الحين؟"
- "لخّص لي الطلبات المعلقة"
- "Which supply point is running low on fuel?"

| النموذج (أمثلة) | الحجم | العتاد المقترح | ملاحظات |
|---|---|---|---|

## 5) كل الإعدادات

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `AZM_AI_PROVIDER` | `none` | `none` = غير مربوط، و `openai` = خادم متوافق |
| `AZM_AI_BASE_URL` | `http://127.0.0.1:8002/v1` | ينتهي بـ `/v1`. لـ Ollama: `http://localhost:11434/v1` |
| `AZM_AI_MODEL` | — | **مطلوب**. بدونه يعتبر غير مربوط |
| `AZM_AI_API_KEY` | — | يُرسل كـ `Authorization: Bearer …` إذا تم تحديده |
| `AZM_AI_TIMEOUT_MS` | `60000` | مهلة انتظار الرد. زِدها للنماذج البطيئة |
| `AZM_AI_TEMPERATURE` | `0.3` | 0 = ردود ثابتة، و 1 = إبداعية |
| `AZM_AI_MAX_HISTORY` | `20` | عدد الرسائل السابقة المرسلة |
| `AZM_AI_CONTEXT_CHARS` | `14000` | حد الأحرف للقطة + السجل + نتائج الأدوات. يصغّر الخادم اللقطة (النقص والطلبات المعلقة أولاً) لتناسب نافذة النموذج، وإذا رد النموذج بأن الطلب أطول من سياقه يعيد المحاولة بنصف الحد مرتين. يناسب `serve-mlx.py` بنافذته الافتراضية 6144 توكن (الحد الآمن المقاس على بطاقة 8GB، مع `--prefill-step 256`)؛ خفّضه إذا شغّلته بـ `--max-context` أصغر |
| `AZM_AI_MAX_TOKENS` | `768` | أقصى طول للرد |
| `AZM_AI_STREAM` | `1` | بث رد المساعد للمتصفح أثناء كتابته. `0` = الرد كامل دفعة وحدة |
| `AZM_AI_NUMBER_CHECK` | `1` | تنبيه آلي بآخر الرد إذا فيه رقم ما له أصل في البيانات؛ 0 = إيقاف |
| `AZM_REPORT_AI_PROVIDER` / `_BASE_URL` / `_MODEL` / `_API_KEY` | `none` / `http://localhost:11434/v1` / — / — | نموذج التقارير (التقرير الذكي وشرح التقارير). محلياً: `openai` و`http://127.0.0.1:8002/v1` و`azm-report-base` |
| `AZM_REPORT_AI_TIMEOUT_MS` / `_TEMPERATURE` / `_MAX_HISTORY` / `_MAX_TOKENS` | `60000` / `0.2` / `12` / `1024` | مثل نظيراتها للمحادثة |
| `AZM_REPORT_AI_CONTEXT_CHARS` | `10000` | حد أحرف الحقائق وفقرات المنهجية في التقرير الذكي؛ ربعه (حتى 3000) للمنهجية |
| `AZM_RAG_URL` | فارغ | خدمة BGE-M3 (`http://127.0.0.1:8010`). فارغ أو متوقف يعني البحث المحلي في `resources/report-knowledge.json` |

ملف `start-azm.cmd` (ومثله `start-azm.sh` على Mac/Linux) في جذر المشروع يضبط كل ما سبق للتشغيل المحلي (8002 و8010) دون الحاجة إلى `.env`، ويشغّل الموقع على المنفذ 5182 بإعدادات الاختبار الثابتة: الحرارة 0، والبث مفعّل، و512 توكن للرد، و8 رسائل للسجل، و10000 حرف للسياق. حالات اختبار البرومبت في `docs/PROMPT_TEST_CASES.md`.

### بث الرد أثناء الكتابة
- المتصفح يرسل `Accept: application/x-ndjson` مع `POST /api/chats` و`POST /api/chats/:id/messages`، والخادم يرد بسطر JSON لكل حدث: `start` ثم `delta` (جزء من النص) أو `reset` (امسح ما وصل لأن الرد طلع استدعاء أداة) ثم `done` ومعه المحادثة كاملة ومحفوظة. التفاصيل في `docs/API.md`.
- بين الخادم والنموذج يُستخدم بث OpenAI SSE (`stream: true`) عبر `modelStream` في `server/ai/providers/openai-compatible.mjs`. استدعاءات الأدوات ما تظهر للمستخدم.
- `scripts/serve-mlx.py` صار يدعم `stream: true`. وإذا رجّعت أي خدمة 400 على البث، يرجع الخادم للطلب العادي تلقائياً.

### كاش البرومبت
- `scripts/serve-mlx.py` يحتفظ بآخر برومبتات محسوبة (`scripts/mlx_prompt_cache.py`)، ويعيد استخدام أطول بداية مشتركة مع الطلب الجديد، ويحسب الباقي بس. النص الناتج نفسه، وأول رد أسرع.
- `--prompt-cache-slots`: الافتراضي `2` (نداء الأداة ونداء الجواب)، و`1` إذا نفدت الذاكرة على بطاقة 8GB، و`0` للإيقاف. كل نسخة تحجز حتى ~0.9GB عند 6144 توكن.
- أي خطأ من MLX يوقف الكاش ويرجع للتوليد العادي تلقائياً.
- سكربت التشغيل يقبل `AZM_MAX_CONTEXT` (6144 افتراضياً) و`AZM_PROMPT_CACHE_SLOTS` (2 افتراضياً). مثال حد 7168 مع نسخة كاش وحدة (جُرّب على بطاقة 8GB):
  ```bash
  AZM_MAX_CONTEXT=7168 AZM_PROMPT_CACHE_SLOTS=1 bash scripts/start-ai.sh
  ```

### تشغيل نموذج واحد للمساعد والاستخراج
- بطاقة 8GB ما تتحمل نسختين، فخدمة وحدة على 8002 تحمّل النموذج مع الأدابتر مرة وحدة وتخدم اسمين:
  - `azm-request-lora`: الأدابتر مفعّل، لاستخراج طلب الوحدة من النص.
  - `azm-report-base`: طبقات LoRA معطّلة مؤقتاً (`scale = 0`)، فيكون الناتج نفس النموذج الأساسي، للمساعد والتقارير.
- الأمر:
  ```bash
  AZM_MAX_CONTEXT=7168 AZM_PROMPT_CACHE_SLOTS=1 bash scripts/start-ai.sh
  ```
- مع هذا التشغيل يكون `AZM_REQUEST_AI_BASE_URL=http://127.0.0.1:8002/v1` في `start-azm.cmd` و `start-azm.sh`.
- الاسم القديم `start-ai-wsl.sh` باقي للتوافق ويشغّل نفس السكربت.
- فحص المنطق بدون MLX: `cd scripts && python prompt-cache-logic-test.py`.
- فحص على النموذج الحقيقي (مرة وحدة داخل WSL، بعد إيقاف خدمة النموذج):
  ```bash
  cd /mnt/c/AZM/scripts && ~/azm-llm/venv/bin/python -B prompt-cache-check.py --model ~/azm-llm/models/qwen3-4b-4bit
  ```
  `PASS: cached output is identical` يعني شغّل الخدمة عادي. `CHECK: outputs differ` يعني شغّلها بـ `AZM_PROMPT_CACHE_SLOTS=0 bash scripts/start-ai.sh`.

### برومبت استخراج الطلب
`REQUEST_SYSTEM_PROMPT` في `server/ai/request-contract.mjs` هو رسالة system المستخدمة في تدريب LoRA (`train.jsonl`) **حرفياً** (875 حرفاً). لا تعدّله إلا مع إعادة التدريب بنفس النص، لأن أي اختلاف يضعف دقة المحوّل. يستخدمه `/api/ai/request-draft` و`scripts/verify-local-ai.mjs`.

> متغيرات النظام تغلب قيم `.env`. أي تغيير في `.env` **يحتاج إعادة تشغيل الخادم**.

## 6) وش يستلم النموذج بالضبط

### تعليمات النظام

النص في `server/ai/prompt.mjs`. باختصار:
- يرد بنفس لغة السؤال.
- يعتمد على اللقطة فقط، وما يخترع أرقام.
- يقول بوضوح إذا المعلومة غير موجودة.
- يرتّب الأولويات: نفد ← حرج ← تحت نقطة الطلب.
- ما يتكلم عن قواعد أو مستودعات أو وحدات خارج صلاحية السائل.
- ما يجمع موارد بوحدات قياس مختلفة في رقم واحد، ويوضح إنه للقراءة فقط إذا طُلب منه تنفيذ إجراء.
- يستدعي أدوات القراءة بنفسه إذا نقصت معلومة، وما يطلب من المستخدم يشغّل أداة.
- **شكل الرد:**
  - الجواب المباشر في أول سطر، ثم حتى 5 نقاط قصيرة.
  - أسماء العرض فقط: لا رموز داخلية (`azm_diesel`، `UNIT-01`)، ولا أسماء حقول (`okCount`)، ولا أسماء أدوات.
  - المخزون بصيغة: النسبة، ثم الكمية من السعة بوحدتها، ثم الحالة (مستوى جيد / تحت نقطة إعادة الطلب / حرج / نافد).
  - حالات الطلب والأولوية والوسيلة بالعربي.

### المنهجية والسياسات العامة في المساعد

مع كل سؤال في المساعد الذكي يسترجع الخادم حتى 3 مقاطع من `resources/report-knowledge.json` (عبر BGE-M3 إذا كان `AZM_RAG_URL` مضبوطاً، وإلا البحث المحلي) ويرسلها رسالة نظام منفصلة بعد اللقطة: «AZM methodology and policies». المقاطع عامة (`visibility: all`) ومفلترة بالصلاحية قبل البحث، فكل دور يقدر يسأل عن القوانين العامة والأساسيات والموافقات والصلاحيات والسياسات. هي شرح فقط وليست مصدر رصيد؛ البيانات التشغيلية تبقى من اللقطة المفلترة: مسؤول الوحدة تفاصيل وحدته كاملة (ومنها الأفراد والمركبات)، ومسؤول القاعدة تفاصيل قاعدته ومراكزها ووحداتها كاملة. تعذّر الاسترجاع لا يوقف الرد. بعد تعديل ملف المعرفة أعد تشغيل خدمة RAG (`rag/service.py`) إذا كانت تعمل.

### لقطة العمليات

تُبنى مع **كل سؤال** من `server/ai/context.mjs`. المثال تحت يوضح اللقطة **الكاملة**، والنموذج يستلم نسخة مصغّرة منها من `server/ai/compact.mjs` حسب `AZM_AI_CONTEXT_CHARS`:
- **مستويات التصغير:** تبدأ بكل النسب. إذا ما كفّت، تُرسل الموارد تحت 45% فقط مع عدد الباقي في `okCount`. وإذا ما كفّت بعد، تُرسل أعداد فقط. وآخر حل: الجهات الأشد نقصاً والمذكورة في السؤال.
- **ما يبقى دائماً:** الطلبات، حتى في أصغر مستوى.
- **ما يُرسل بأرقامه الفعلية:** الموارد والمواقع المذكورة في السؤال، مثل «الديزل» أو «قاعدة الشمال». تُرسل في `askedResources` بالنسبة والكمية والسعة، والمطابقة تشمل الأسماء البديلة من `resources/items.json`.

### شرح تقارير الإمداد بالنموذج

في صفحة «التقارير» اضغط «اشرح التقرير بالذكاء الاصطناعي». يرسل المتصفح **الفلاتر واللغة فقط** إلى `POST /api/reports/explain`. يعيد الخادم حساب التقرير المفلتر بواسطة `buildReport`، ثم يرسل إلى النموذج الفترة، أعداد الطلبات وكمياتها، إجماليات القواعد والكيانات الظاهرة، والصادر من الرياض. لا تُرسل ملاحظات الطلبات أو السجل الخام. يذكر الشرح أن الاستهلاك محاكى وأن التحويل داخل القاعدة لا يُحسب موردًا جديدًا. إذا كان النموذج غير مربوط تظهر رسالة بذلك، وتستمر التقارير الرقمية بالعمل.

لم يُضف إلى المشروع نموذج مدرّب على سيناريوهات طلبات عزم. يمكن ضبط أي خادم متوافق كما سبق؛ التدريب لا يغني عن لقطة البيانات الحية.

### ربط خدمة RAG المتجهية الاختيارية

خدمة `rag/service.py` تسترجع بـ `BAAI/bge-m3`:
- تعمل **على المعالج** حتى ما تزاحم النموذج على البطاقة.
- `GET /health` للحالة.
- تعيد بناء الفهرس تلقائياً إذا تغير المرجع.
- تشتغل بـ `bash scripts/start-rag.sh`.

إذا كانت متوقفة، يرجع الخادم للبحث النصي المحلي دون فشل. خطوات WSL والبناء والاختبار في [RAG_SETUP.md](RAG_SETUP.md). المخرجات التفسيرية لا تحل محل أرقام التقرير الحية.

لما تنضاف مستندات وبحث متجهي، الفلترة تكون **قبل البحث** وليس بعده:

1. كل مستند/مقطع يحمل بيانات وصفية بنفس معرّفات النظام: `{ baseIds?: [...], entityIds?: [...], unitIds?: [...], visibility?: 'all' }` (معرّفات القواعد والمراكز = معرّفات نقاط الخريطة، والوحدات `UNIT-NN`).
2. قبل البحث: `retrievalFilter(user)` من `server/store/scope.mjs` يرجع `{ all, role, baseIds, entityIds, unitIds }` — يتحول لفلتر بيانات وصفية في قاعدة المتجهات.
3. للتحقق من نتيجة مفردة: `canAccessDocument(user, meta)`.
4. ما يوصل للنموذج إلا نتائج داخل نطاق السائل، مع نفس لقطة `buildContext(user)`.

## 8) الأمان وسرية البيانات

- **النموذج المحلي (Ollama وأشباهه)** هو الخيار الموصى به. البيانات ما تطلع من الجهاز أو الشبكة.
- **الخدمات السحابية:** كل سؤال يرسل لقطة العمليات للخدمة. لا تستخدمها مع بيانات حقيقية حساسة.
- **صلاحيات النموذج:** النموذج **يقرأ فقط**. ما عنده أي صلاحية لتنفيذ إجراءات (اعتماد، تعديل، حذف). الخادم ما ينفّذ أي شي من نص الرد.
- **مفتاح API** يكون في `.env` فقط. هذا الملف مستثنى من `npm run package` ومن git.

## 9) حل المشاكل

| العرض | السبب والحل |
|---|---|
| يطبع `not connected (AZM_AI_PROVIDER=none)` | `.env` غير موجود أو `AZM_AI_PROVIDER` غير مضبوط، أو ما أعدت تشغيل الخادم |
| `connected` لكن الرد "تعذّر الحصول على رد" | السبب يُطبع في طرفية الخادم: `[AI] openai/…: …`. أكثر الأسباب شيوعاً تحت |
| `fetch failed` | خادم النموذج مطفي أو العنوان خطأ. جرّب `curl http://localhost:11434/v1/models` |
| `HTTP 404` | اسم النموذج غير موجود في الخادم. شوف `ollama list` |
| بطء أو `aborted` | النموذج كبير على العتاد. جرّب نموذج أصغر، أو زِد `AZM_AI_TIMEOUT_MS` |
| الرد بلغة غلط أو يخترع أرقام | استخدم نموذج أقوى، أو شدّد التعليمات في `prompt.mjs`، أو قلّل `AZM_AI_TEMPERATURE` |
| `ai_unavailable` في طرفية الخادم مع `serve-mlx.py` | الخدمة متوقفة، أو ردّت `inference_failed`. السبب يُطبع في نافذة WSL، مثل `out of memory` إذا شغّلت نسختين على بطاقة 8GB. شغّل `scripts/start-ai.sh` وحده (نسخة وحدة تخدم الاسمين) |
| `ai_context_too_long` | الطلب أكبر من `--max-context` حتى بعد التصغير والإعادة. خفّض `AZM_AI_CONTEXT_CHARS` أو `AZM_REPORT_AI_CONTEXT_CHARS` |
| `out of memory` بعد تفعيل كاش البرومبت | شغّل `serve-mlx.py` بـ `--prompt-cache-slots 1` |
| `Address already in use` في WSL | الخدمة شغالة أصلاً في نافذة ثانية. كمّل، أو أوقفها بـ `pkill -f serve-mlx.py` |

## 10) التوسيع

### موصّل لخادم غير متوافق مع OpenAI

```js
// server/ai/providers/my-provider.mjs
export async function myProvider({ baseUrl, model, apiKey, timeoutMs }, messages) {
  // messages: [{ role: 'system'|'user'|'assistant', content: '...' }]
  const res = await fetch(`${baseUrl}/generate`, { method: 'POST', body: JSON.stringify({ model, messages }) });
  return (await res.json()).text;   // نص الرد فقط
}
```

```js
// server/ai/index.mjs
import { myProvider } from './providers/my-provider.mjs';
const providers = { openai: chatCompletion, mine: myProvider };
```

ثم في `.env`: `AZM_AI_PROVIDER=mine`.

## مسودة الطلب وسياسة الأصناف (v8)

- كل مادة في رد `POST /api/ai/request-draft` تحمل `requestable` (صنف تشغيلي للوحدة: الأغذية والمياه المخصصة أو نوع وقودها) و`blockedReason` عند الرفض. المادة غير القابلة للطلب تظهر في المسودة معلَّمة ولا تدخل نموذج الطلب؛ لا يُنشأ أي طلب تلقائياً.
- الاسم العربي الفصيح (`nameAr` في `resources/items.json`) مضاف للمرادفات، وتبقى الأسماء العامية والإنجليزية مرادفات. الاختبار يتحقق ألا يطابق مرادف صنفين.
- لقطة النموذج (`server/ai/context.mjs`) تضيف `fuelType` و`requestableResources` لكل وحدة، و`shipmentStatus` يميز `awaiting_commander_decision` و`approved_awaiting_base_manager_execution_no_stock_deducted` و`in_transit`، وتبقى مفلترة بنفس نطاق المستخدم.
# ربط AI في v9

التشغيل على Mac وويندوز (WSL): [SETUP.md](SETUP.md). نموذج LoRA الموجود في `models/request-adapter/` للاستخراج JSON فقط (`/api/ai/request-draft`)، والمحادثة العامة والتقرير الذكي على النموذج الأساسي (`azm-report-base`، نفس الخدمة 8002 والأدابتر معطّل). المخزون والحسابات لا يتغيران بمخرجات النموذج؛ إنشاء الطلب من API بعد مراجعة المسودة. خدمة `scripts/serve-mlx.py` تفهم أدوات القراءة المعتمدة على هيئة Qwen `<tool_call>` وتعيدها بصيغة OpenAI؛ الخادم يفلتر نتائجها حسب الجلسة. استرجاع التقارير المحلي من `resources/report-knowledge.json` لا يحتاج Chroma، ويمكن استبداله بمسترجع خارجي عبر `AZM_RAG_URL` وعقد `server/ai/rag-contract.mjs`؛ وثائق زميلك ذات المنهجية المختلفة لم تُدمج. الاختبار الحقيقي للأوزان الأساسية يعتمد على وجود ملفها على جهازك في WSL.
