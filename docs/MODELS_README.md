# تشغيل نماذج عزم وحدودها

> الأدابتر المدرب في `models/request-adapter/` (من صفحة Releases)، والنموذج الأساسي ينزله `scripts/setup-ai.sh`. خطوات التشغيل الفعلية والمتطلبات في [SETUP.md](SETUP.md)، ونتيجة التقييم في [eval-results/report.md](../eval-results/report.md). التقرير الذكي في سجل العمليات يسترجع نصوصاً من مرجع منهجية عزم (BGE-M3 أو بحث محلي)، بينما الأرقام الحية يحسبها الخادم. الفقرات التالية توثق اختبارات الربط الأولى.

ثلاث خدمات مستقلة: استخراج طلب JSON عبر `AZM_REQUEST_AI_*`، وإجابات الحالة والاستخدام عبر `AZM_AI_*`، والتقرير الذكي وشرح التقارير عبر `AZM_REPORT_AI_*`. يظل `provider=none` صالحاً لكل خدمة، وتبقى الطلبات والمخزون والتعبئة والسجل تعمل دون نموذج.

فُحص `all_examples.csv`: 2000 صف، منها1600 تدريب و200 تحقق و200 اختبار؛ جميع المخرجات فيها `items,priority,deadline`، وحقول المادة `item,supply_class,quantity,unit_of_measure`. المهمة استخراج احتياج، وليست شرح إجراءات النظام. الأدابتر مدرج في حزمة v9، أما أوزان النموذج الأساسي وبيانات التدريب فغير مدرجة.

فُحص تحميل Qwen3-4B ذي التكميم4بت مع أدابتر LoRA محلي عبر MLX على WSL. الاختبار الحقيقي القصير أعاد المواد والكميات والأولوية الصحيحة مع فئات خاطئة؛ صححها كتالوج عزم إلى `III` مع تحذيرين، ووصلت المسودة عبر API دون إنشاء طلب أو تغيير المخزون. التفاصيل والنتائج غير الكاملة في [README السابق](history/README_V9.md). لا نستنتج جودة عامة من نجاح التحميل أو من عينة واحدة.

خدمة اختيارية فوق بيئة MLX الموجودة، دون تثبيت اعتماديات داخل تطبيق عزم:

```bash
python scripts/serve-mlx.py --model /path/to/base-model --adapter /path/to/lora --name azm-request-lora --base-name azm-report-base --port 8002
```

تشغّل الأمر من مجلد المشروع داخل WSL باستخدام Python البيئة التي تحتوي MLX. الخدمة محلية وتعرض `/v1/models` و`/v1/chat/completions`، وتحمّل النموذج والأدابتر عند البداية. نموذج أساسي بلا أدابتر ممكن بحذف `--adapter`، لكنه ليس الاختبار نفسه. حدود الخدمة الافتراضية 6144 رمزاً للسياق (`--max-context`) و1024 للإجابة، وتعالج البرومبت على دفعات 256 رمزاً (`--prefill-step`) وتفرّغ ذاكرة MLX المؤقتة بعد كل طلب، وتعالج الاستدلال بالتسلسل.

القياس على بطاقة 8GB:
- بدفعات 2048 (افتراضي MLX) بلغت الذروة 6.8GB، ونفدت الذاكرة من ثاني طلب.
- بدفعات 256 بقيت الذروة 3.5GB.
- برومبت 7200 رمز نجح بذروة 4.9GB، و8100 نفدت معه الذاكرة.

لذلك تشغّل `scripts/start-ai.sh` نسخة وحدة من النموذج تخدم الاسمين (`azm-request-lora` بالأدابتر و `azm-report-base` بدونه)؛ تشغيل نسختين معاً على 8GB غير مستقر. سبب أي فشل يُطبع في نافذة WSL.

إعدادات الاستخراج المقابلة في `.env` محلياً:

```ini
AZM_REQUEST_AI_PROVIDER=openai
AZM_REQUEST_AI_BASE_URL=http://127.0.0.1:8002/v1
AZM_REQUEST_AI_MODEL=azm-request-lora
AZM_REQUEST_AI_TIMEOUT_MS=180000
AZM_REQUEST_AI_MAX_TOKENS=512
```

بعد تعديل إعدادات الخادم أعد تشغيل خادم عزم الذي تديره، مع نفس `AZM_DATA_DIR` والمنفذ (5182 في `start-azm.cmd` / `start-azm.sh`). لا تشغّل خادمين على بيانات واحدة. لا حاجة لتغيير إعدادات المحادثة والتقارير حتى تتوفر نماذج مناسبة لهما. لا تضع LoRA الاستخراج كنموذج إجابة عام.

اختبار معزول على بيانات مؤقتة، في PowerShell مع الخدمة قائمة:

```powershell
$env:AZM_TEST_LORA_URL='http://127.0.0.1:8002/v1'
$env:AZM_TEST_LORA_MODEL='azm-request-lora'
node scripts/verify-local-ai.mjs
node scripts/ui-draft-test.mjs
```

الأول يختبر الاستدلال الحقيقي ثم API عزم، ويتحقق من المواد والكميات والفئة المرجعية وعدم إنشاء عمليات. الثاني يشغّل مكوّن المساعد الحقيقي بمحاكاة hooks للتحقق من عرض المسودة والتحذير وفتح المراجعة دون إنشاء طلب، وتعطيل الانتقال عند نقص الكمية. لا يمثل الثاني فحصاً بصرياً في المتصفح.

أدوات القراءة المتاحة: `read_requests` و`read_inventory` و`read_report`؛ مخططاتها في `/api/ai/tools`. الخادم يرفض الأدوات غير المعروفة والحقول الزائدة والجهات خارج النطاق. يستلم النموذج النتائج المفلترة فقط؛ لا تنفذ مخرجاته إنشاءً أو اعتماداً أو خصماً. عقد المسودة في `/api/ai/request-schema` والتفاصيل في [API](API.md).

استرجاع النصوص المحلي في `resources/report-knowledge.json` (14 فقرة) يعمل بدون فهرس خارجي ويعيد بحد أقصى ستة مقاطع من منهجية عزم الحالية؛ التقرير الذكي يطلب أربعة. خدمة BGE-M3 المرفقة (`rag/service.py`، `scripts/start-rag.sh`) تعمل على المعالج على المنفذ 8010، ويمكن بدلها تخصيص `AZM_RAG_URL` لمسترجع متجهي خارجي متوافق، على أن يفلتر الوثائق قبل الاسترجاع بحسب `reportRetrievalInput` ويعيد `{chunks:[{id,text,metadata}]}`؛ يتحقق الخادم من نطاق كل مقطع بعده. الأرصدة الحية تأتي دائماً من تقرير الخادم. لا تُدخل وثائق مشروع الزميل القديمة كما هي؛ صلاحياتها ومنهجية التوريد مختلفة.
