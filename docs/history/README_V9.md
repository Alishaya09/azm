### نتيجة اختبار LoRA وحدود التكامل

ملف `all_examples.csv` الذي فُحص يحتوي 2000 مثال لتحويل نص طلب إمداد إلى JSON، وليس لتدريب محادثة عامة. الحقول الرئيسية هي `items` و`priority` و`deadline`؛ وكل مادة تحتوي `item` و`supply_class` و`quantity` و`unit_of_measure`.

في الاختبار الفعلي الذي أجراه المستخدم، نجح تحميل LoRA واستخرج طلب «نبغى 12 برميل ديزل و5 علب زيت محرك، الأولوية عاجلة»: ديزل 12 `barrel` وزيت محرك 5 `can` وأولوية `urgent`. لكنه أعاد الفئتين `fuel` و`engine oil` بدلاً من `III`؛ لذلك لا نعتبر دقة الاستخراج كاملة. وفي اختبار محلي موجّه بالصيغة، استخرج النموذج المواد والكميات والفئة، لكنه أغفل `deadline`. غياب الموعد يُطبّع إلى `null` مع تحذير ولا يُخترع موعد.

المسار المعتمد: استخراج JSON ← مطابقة اسم المادة مطابقة صريحة وغير ملتبسة بكتالوج عزم ← أخذ `supply_class` من الكتالوج وتسجيل اختلاف النموذج كتحذير ← التحقق من وحدات القياس وأصناف الوحدة ← عرض مسودة للمراجعة والتعديل ← إنشاء الطلب عبر API فقط بعد تأكيد المستخدم وفحص الخادم. الاسم غير المعروف أو المشترك بين أكثر من صنف يُرفض؛ والكمية الناقصة تبقى بحاجة إلى توضيح. الاستخراج وعرض المسودة لا ينشئان طلباً ولا يخصمان مخزوناً.

نموذج الاستخراج مستقل عن الإجابة عن حالة الطلب والمخزون وطريقة الاستخدام، وعن التقرير الذكي في سجل العمليات. الإجابات تعتمد على بيانات مفلترة حسب صلاحيات المستخدم. RAG بنموذج التمثيل BGE-M3 متاح كخدمة اختيارية (`scripts/start-rag-wsl.sh`)، ويرجع النظام للبحث المحلي إن لم تكن شغالة. إعداد اسم نموذج أو عنوان خدمة لا يثبت نجاح الاستدلال. الاختبارات الآلية المزودة بمزوّد تجريبي تتحقق من تصحيح الفئة ورفض الأسماء غير المعروفة والملتبسة وعدم إنشاء عمليات أثناء المراجعة؛ وهي لا تثبت جودة LoRA الحقيقي على جميع الطلبات.

اختبار محلي إضافي على النموذج الأساسي مع LoRA عبر خدمة MLX نجح حتى `POST /api/ai/request-draft` ببيانات عزم مؤقتة: أعاد النموذج الفئتين الخاطئتين `regular` و`engine`، وصححهما الخادم إلى `III` مع تحذيرين. المسودة احتوت ديزل 12 برميل = 2400 لتر وزيت محرك 5 علب = 20 لتر، وأولوية عاجلة وموعداً `null`. تحقق الاختبار من عدم إنشاء طلب أو تغيير المخزون. نجح ذلك مع prompt استخراج قصير؛ prompt أطول أعاد صيغة رُفضت بـ `invalid_model_json`. هذه نتيجة حالة اختبار واحدة ولا تعني ضمان دقة النموذج. يمكن إعادة الاختبار باستخدام `scripts/verify-local-ai.mjs` مع `AZM_TEST_LORA_URL` و`AZM_TEST_LORA_MODEL`؛ ويتطلب خدمة نموذج قائمة، ولا يستخدم بيانات `data/` الحية.

> **هذه النسخة:** قاعدة SQLite مستقلة لكل قاعدة ومركز ووحدة في `data/entities/`، وأصناف التدريب الأربعون تضاف تلقائياً للكتالوج، وعقد JSON لاستخراج مسودة طلب، و**تقرير ذكي داخل سجل العمليات** (لعملية أو عمليات محددة أو فترة) يسترجع منهجية عزم بـ BGE-M3 أو بحث محلي، وحلّ محل صفحة شات التقارير. تتطلب Node.js 24.15 أو أحدث.

> **أرشيف v5:** [السلسلة السابقة](docs/SUPPLY_V5.md). السلوك الحالي موضح في [مرجع v9](docs/SUPPLY_V9.md).

> **جلسات التبويبات:** افتح الأدوار الثلاثة في ثلاثة تبويبات عادية من نفس المتصفح والعنوان. كل تبويب يحتفظ بحسابه بعد تحديث الصفحة، وخروجه لا يخرج الباقين. معرّف غير سري في `sessionStorage` يختار كوكي `HttpOnly` خاصاً به؛ جميع طلبات API تبقى مفلترة على الخادم. بعد تحديث كود الجلسات أعد تشغيل الخادم بنفس مجلد البيانات ثم حدّث التبويبات وسجّل الدخول مجدداً.

منصة ويب لإدارة الإمداد اللوجستي الميداني. تعرض حالة الوحدات على خريطة حيّة، وتستقبل طلبات الإمداد وتعتمدها، وتتبّع القوافل وهي تتحرك على الطرق، وتحاكي استهلاك المخزون مع تنبيهات تلقائية. وفيها مساعد ذكي جاهز للربط بنموذج لغة محلي (On-Premise).

- **اللغة:** عربي وإنجليزي بزر واحد، والتصميم ثابت من اليسار في اللغتين.
- **التشغيل:** Node.js فقط، بدون تثبيت أي حزم (`npm install` غير مطلوب).
- **الحالة:** نسخة عرض (Demo). البيانات والمحاكاة تجريبية.

> **أول مرة؟ ابدأ من [GETTING_STARTED.md](GETTING_STARTED.md)**: التشغيل وإنشاء حساب المسؤول الخاص فيك في 5 دقايق. لتشغيل الذكاء الاصطناعي (النموذج وRAG) اتبع بعده [LOCAL_MODEL_SETUP.md](LOCAL_MODEL_SETUP.md).

## المزايا

| الميزة | الوصف |
|---|---|
| **الخريطة التكتيكية** | خريطة حقيقية (Leaflet) بصور قمر صناعي وأسماء مدن، فيها القواعد ومراكز الإمداد والوحدات وخطوط الإمداد. الضغط على أي نقطة يقرّب لها ويعرض بياناتها. |
| **تعديل الخريطة** | المسؤول يضيف قواعد ومراكز إمداد ووحدات بأي عدد ويسميها، ويربط بينها بمسار بري (يُرسم على الطرق الفعلية عبر OSRM) أو جوي. |
| **الوحدات** | كل نقطة وحدة على الخريطة = وحدة حقيقية بمخزون (ذخيرة، وقود، غذاء، دواء)، ومؤشرات MCR و DOS. |
| **محاكاة الاستهلاك** | تعمل على الخادم: المخزون ينزل حسب معدل التشغيل (OPTEMPO)، والسرعة قابلة للتغيير (×1 إلى ×20)، مع وضع طوارئ. |
| **التنبيهات** | تنبيه تلقائي عند النزول تحت 45% (نقطة الطلب) و25% (حرج) و0% (نفاد)، مع نافذة منبثقة وزر طلب سريع. |
| **طلبات الإمداد** | نموذج احترافي: مواد متعددة بكميات (بالنسبة والكمية الفعلية)، وسيلة نقل، أولوية، ومبررات، مع ملخص جانبي. |
| **دورة الطلب** | القائد وحده يعتمد أو يرفض أو يحوّل لطائرة؛ مسؤول القاعدة يتابع ويعلّق. لكل طلب أولوية وتاريخ حالة. |
| **تتبع القوافل** | عند الاعتماد تتحرك أيقونة 🚛 أو ✈️ على المسار الفعلي من نقطة التوريد إلى الوحدة، وتعبّي المخزون عند الوصول. |
| **المساعد الذكي** | زر عائم بشكل واجهات المحادثة الحديثة، يحفظ المحادثات لكل مستخدم. جاهز للربط بنموذج محلي، ويرسل له لقطة حية من بيانات العمليات. |
| **قواعد البيانات (القواعد)** | لكل قاعدة مستودع، ولكل مركز إمداد ووحدة تابعة لها مخزون مستقل بسعة ورصيد افتتاحي وسجل حركات. القائد ينشئ الكيانات ويحدد التبعية (إلزامية)، ويضيف مخزون خارجي للقواعد؛ والقائد ومسؤول القاعدة يحوّلون بين المستودعات. الإجماليات تفصل الموجود عن الشحنات بالطريق. |
| **الصرف من المستودع** | اعتماد الطلب يخصم الكميات الفعلية من مستودع نقطة التوريد، ويُرفض إذا المخزون ما يكفي. |
| **الحسابات** | ملف كامل لكل مستخدم: الاسم، الرتبة، الرقم العسكري، الجوال، المسمى، الحالة، وآخر دخول. |
| **طلب حساب من الخارج** | من شاشة الدخول. الحساب يبقى "بانتظار الموافقة" لين يعتمده المسؤول، أو يرفضه بسبب يظهر للمتقدم. |
| **التقارير** | المخزون التفصيلي، المؤشرات، **تقارير الإمداد الفعلية** (الافتتاحي والختامي، الإضافات، التحويلات، الإرسال والتسليم، الاستهلاك المحاكى، بالفلترة والتصدير CSV)، وشرح اختياري للنتائج عبر نموذج لغة ضمن نطاق المستخدم؛ سجل حركات المخزون الدائم، وداشبورد برسوم تفاعلية. |
| **التقرير الذكي للعمليات** | داخل سجل العمليات: تقرير لعملية واحدة (زر 📈) أو عمليات محددة بالمربعات أو فترة من تاريخ إلى تاريخ مع الفلاتر. يعرض بطاقات وجداول كميات وأبرز الأرقام محسوبة بالخادم، ثم شرحاً من النموذج مع مراجع المنهجية (RAG)، وأسئلة لاحقة ونسخاً وطباعة وتقارير محفوظة. |
| **المورد الافتراضي** | بلا نقطة على الخريطة؛ القائد يزوّد مستودعات القواعد فقط بسبب وكميات مسجلة. مسؤول القاعدة يرفع احتياجاً؛ تاريخ شحنات الرياض محفوظ. |
| **كتالوج الموارد** | القائد يضيف الأصناف ويعدّل أسماءها ووحدات قياسها وسعاتها ومعدلات استهلاكها أو يعطّلها، وأصناف التدريب الأربعون تُضاف تلقائياً للكتالوج. القائد يحدد أصناف كل وحدة من صفحة قواعد البيانات؛ الوحدات لا ترث كل الأصناف تلقائياً. |
| **الأدوار الثلاثة** | القائد الرئيسي، مسؤول القاعدة، مسؤول الوحدة — لكل دور واجهته ونطاقه، وتشتغل بالتزامن على خادم واحد. |
| **الشرح المدمج** | نافذتا "كيف يعمل؟" و OPTECHO™ باقيتان في `src/modals/`، وأُزيلت أزرارهما من الشريط العلوي. |

## الحسابات والصلاحيات

عند أول تشغيل ينشئ الخادم حسابين ويطبع كلمات المرور في الطرفية وفي `data/FIRST_RUN_CREDENTIALS.txt`. وأي شخص يقدر يطلب حساب من شاشة الدخول ("طلب حساب جديد")، والحساب ما يشتغل لين يوافق عليه المسؤول من صفحة المستخدمين.

حالات الحساب: **نشط**، **بانتظار الموافقة**، **موقوف** (يطلع من النظام فوراً)، و**مرفوض**.

ثلاثة أدوار (ويمكن إنشاء أكثر من حساب لكل دور)، والواجهة تتحدد تلقائياً حسب الحساب:

| | القائد الرئيسي (`admin`) | مسؤول القاعدة (`base_manager`) | مسؤول الوحدة (`user`) |
|---|---|---|---|
| النطاق | كل القواعد | قاعدته ومراكزها ووحداتها | وحدته فقط |
| الخريطة | يشوف ويعدّل | قاعدته وما تحتها كاملة (قراءة)، وبقية القواعد والوحدات **بالاسم فقط** | وحدته وسلسلة إمدادها (أسماء) |
| المخزون | الكل، مع الإجماليات والشحنات بالطريق | قاعدته وما تحتها | مخزون وحدته كامل (بدون أرصدة المستودعات) |
| طلبات الإمداد | ينشئ لأي وحدة، يكلّف قاعدة أو يرسل مباشرة، يرفض | ينشئ لوحدات قاعدته، يوافق ويرسل من مستودعات قاعدته، ويباشر تكليفات القائد | ينشئ لوحدته ويتابع ويعلّق |
| إنشاء القواعد ومراكز الإمداد | ✓ | ✗ | ✗ |
| إنشاء الوحدات | لأي قاعدة | لقاعدته فقط | ✗ |
| تحويل مخزون | أي مستودعين (بين قاعدتين بسبب مسجّل) | داخل قاعدته | ✗ |
| تعبئة القواعد من المركز الرئيسي | ✓ (وحده) | ✗ | ✗ |
| سرعة المحاكاة ×1/×5/×10/×20 (تطبّق على الجميع) | ✓ | ✓ | ✓ |
| إيقاف المحاكاة ⏸ (وإعادة تشغيلها بعد إيقافه) | ✓ | ✗ | ✗ |
| الحسابات وطلبات الانضمام | كل الحسابات: إنشاء، تعديل، أدوار، موافقة، إيقاف، حذف | يشوف حسابات قاعدته، يوافق/يرفض طلبات الانضمام لوحداته، ويوقف/يفعّل مسؤولي وحداته | ✗ |
| التقارير والسجل | الكل | قاعدته | وحدته |
| المساعد الذكي (قراءة فقط) | كل البيانات + القوانين والسياسات | تفاصيل قاعدته كاملة + القوانين العامة والموافقات والسياسات | تفاصيل وحدته كاملة + القوانين العامة والموافقات والسياسات |

الصلاحيات تُفرض في **الخادم** على كل API (`server/store/scope.mjs`)، والبيانات خارج النطاق ما تنرسل للمتصفح أصلاً. القائد ومسؤول القاعدة ومسؤول الوحدة يشتغلون **بنفس الوقت** على خادم واحد بجلسات مستقلة — التفاصيل في [docs/SCENARIOS.md](docs/SCENARIOS.md) (سيناريو 14).

## التقنيات المستخدمة

- **الخادم:** Node.js (≥ 24.15) بوحدات ES، بدون أي مكتبة خارجية. يستخدم `node:sqlite` و`http` و`crypto` و`fs` المدمجة.
- **الواجهة:** React 18 + JSX، يحوّلها Babel داخل المتصفح. ما فيه أداة بناء (bundler).
- **الخريطة:** Leaflet 1.9.4.
- **المكتبات** محفوظة محلياً في `vendor/`، فما تحتاج تنزيل أي حزم.
- **التخزين:** SQLite مستقل لكل جهة مع ملفات JSON لفهرس النظام والحسابات والمحادثات في `data/`.

## كيف يشتغل النظام

```
 المتصفح (React)                                   الخادم (Node.js)
 ───────────────                                   ────────────────
 App.jsx ── كل 3 ثوانٍ ──► GET /api/state ──► advanceSim()   ← ينقص المخزون حسب الوقت
                                              deliverDueConvoys() ← القوافل الواصلة تعبّي المخزون
          ◄── requests, stocks, alerts, layout, sim ──┘   (مفلترة حسب صلاحية المستخدم)

 الخريطة: يحسب المسار (Dijkstra على الروابط + طرق OSRM)
 المسؤول يعتمد طلب ──► POST /api/requests/:id/approve {route} ──► يبدأ التتبع بساعات المحاكاة

 المساعد ──► POST /api/chats ──► ai/generateReply() ──► النموذج (إذا مربوط) + لقطة العمليات
```

- **المحاكاة على الخادم:** كل المستخدمين يشوفون نفس الأرقام، والاستهلاك يستمر حتى لو الصفحة مسكّرة.
- **الوقت:** كل ساعة تشغيلية = دقيقة فعلية (`AZM_HOUR_MS`). سرعة المحاكاة تسرّع الاستهلاك والقوافل معاً.
- **المسارات:** مصدر كل شحنة يُختار عند الاعتماد (مسؤول القاعدة: مستودع قاعدته أو مراكزها، والقائد: أي مستودع)، والمسار يُحسب من المصدر المختار فعلاً — ما يُستبدل تلقائياً بمصدر أقرب. الشاحنة تمشي على الروابط البرية بسرعة 60 كم/س، والطائرة على الروابط الجوية أو مباشرة من المصدر بسرعة 240 كم/س.

التفاصيل الكاملة (المعادلات، الصلاحيات، تدفق البيانات) في [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## البيانات والتخزين

كل البيانات في مجلد `data/` (أو المسار المحدد في `AZM_DATA_DIR`):

| الملف | المحتوى |
|---|---|
| `users.json` | الحسابات (كلمات المرور مشفّرة بـ scrypt) |
| `state.json` | فهرس الجهات والخريطة والكتالوج والمحاكاة؛ مخزون الجهات وطلباتها وحركاتها في `entities/` |
| `chats.json` | محادثات المساعد الذكي لكل مستخدم، وتقارير العمليات الذكية المحفوظة |
| `FIRST_RUN_CREDENTIALS.txt` | كلمات مرور أول تشغيل — **احذفه بعد قراءته** |

- **إعادة الضبط من الصفر:** أوقف الخادم وخذ نسخة احتياطية من `data/` كاملاً؛ لا تحذف `state.json` وحده لأن ملفات `entities/` مرتبطة بفهرسه.
- **عند مشاركة المشروع:** لا ترسل مجلد `data/` ولا ملف `.env`.

## الخدمات الخارجية

الخادم والمكتبات يشتغلون بدون إنترنت، لكن الواجهة تستخدم هذي الخدمات إذا توفر اتصال:

| الخدمة | الاستخدام | بدون إنترنت |
|---|---|---|
| Esri / CARTO / OpenStreetMap | صور الخريطة وأسماء المدن | الخريطة تظهر فاضية، والنقاط والخطوط تشتغل |
| OSRM (router.project-osrm.org) | رسم المسار البري على الطرق الفعلية | يُرسم خط مستقيم ويُعلَّم "تقريبي" |
| Google Fonts | خطوط Tajawal و JetBrains Mono | يُستخدم خط النظام |

للنشر داخل شبكة مغلقة: استضف خادم خرائط (Tile Server) وخادم OSRM محلياً، وغيّر الروابط في `src/map/TacticalMap.jsx` و `src/domain/routing.jsx`.

## الأوامر

| الأمر | الوظيفة |
|---|---|
| `node scripts/setup.mjs` | إنشاء حساب المسؤول الخاص بك (قبل أول تشغيل). `--reset-admin` لإعادة تعيين كلمة المرور |
| `npm start` أو `node server.mjs` | تشغيل النظام على http://localhost:5173 |
| `npm run check` | فحص سلامة الكود بدون تشغيل |
| **قواعد البيانات (القواعد)** | لكل قاعدة مستودع، ولكل مركز إمداد ووحدة تابعة لها مخزون مستقل بسعة ورصيد افتتاحي وسجل حركات. القائد ينشئ الكيانات ويحدد التبعية (إلزامية)، ويضيف مخزون خارجي للقواعد؛ والقائد ومسؤول القاعدة يحوّلون بين المستودعات. الإجماليات تفصل الموجود عن الشحنات بالطريق. |
| `npm run package` | نسخة نظيفة للإرسال في `release/` (بدون `data/` و `.env`) |
| `npm test` | اختبار شامل للخادم (يستخدم بيانات مؤقتة، ما يلمس `data/`) |
| `npm run build` ثم `npm run preview` | بناء وتشغيل نسخة ثابتة من `dist/` |
| `npm run mock-llm` | تشغيل نموذج وهمي لتجربة ربط المساعد الذكي |
